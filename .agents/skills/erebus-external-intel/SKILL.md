# External intel

Use intel when it can change whether to pursue, test, narrow, or report a candidate. Prefer primary sources: current documentation, source, tests, release notes, issues, pull requests, advisories, and vendor statements.

Establish expected behavior, affected versions, correct defaults, component ownership, public-known status, and the exact fix boundary. Compare prior work by root cause, reachable mechanism, attacker path, boundary, deployment, and fix, not by keywords or a similar impact label.

Search before deep investment and again when a new symbol, dependency, behavior, or version gives a sharper query. Keep sourced fact separate from inference. Old public knowledge may be stale; verify current claims when they matter.

Return only the facts that change the research decision, with direct source links and any unresolved mismatch.
